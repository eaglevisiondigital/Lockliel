# Protected deployment receipt adapters

Local preparation only. Importing `scripts/member-hosted/provider-receipts.mjs` performs no network, credential, Auth or deployment operation. All current tests use synthetic metadata and injected mock transports under the network guard.

## Authority and interface

Construct `createProviderReceiptReader({request,publicRequest,now})` only inside reviewed operator code. `request` is an authenticated exact-origin HTTPS transport; it receives `{method,path,redirect:'error'}` and returns `{status,data,url,redirected:false}`. Its URL must exactly equal `https://api.netlify.com` plus the requested path. `publicRequest` is separately credential-free, exact immutable-origin HTTPS with redirects denied. It must never reuse the authenticated provider transport or its headers.

The reader's `captureBaseline`, `verifyReservation`, `verifyFinalized` and `verifyRetirement` return opaque, reader-scoped handles. Caller JSON, cloned handles, application metadata, page/header echoes and receipts from another reader cannot provide authority. The JavaScript host and injected transport remain trusted; a WeakMap is not a cryptographic signature against malicious operator code.

Publication proof requires complete bounded pagination, duplicate denial, exact site/team, explicit site publication fields, complete historical inventory, unchanged aliases and two consistent deployment reads. Optional raw draft forms true/null/omitted are recorded separately. Logical draft=true is derived only from independent explicit unpublished authority. Draft=false, absent published_at, wrong commit_ref, extra deployment or alias change deny. Historical snapshots remain valid for cleanup beyond five minutes; current publication/retirement observations must be fresh.

Retirement requires scoped/global provider404, list absence, preservation, page404 and all three custom API/direct-function URLs404. Auth URLs are checked with both GET and empty credential-free POST. A GET404 alone cannot certify a POST endpoint is gone.

## Artifact, configuration and behavior evidence

`createArtifactReceiptTransport({request,pin,files,now}).upload` observes actual copied bytes sent to exact-ID upload endpoints and raw provider acknowledgments. Static files bridge SHA1; native ZIP archives bridge SHA256. File size and both local hash domains are checked before transport. `capture()` requires a complete approved artifact bridge. Each artifact needs either its own actual upload ACK, an ACK for an identical required content-addressed blob, or an opaque exact finalization request/map plus provider required-digest subset and independently fresh same-ID ready/publication evidence establishing provider-side reuse. A required digest with no upload ACK remains a hold; missing/unknown required metadata cannot imply reuse. Site-level file/function lists are not immutable-deployment evidence.

The cached official Netlify CLI27.12.0 `hash-fns.js` defaults to SHA256 and hashes the complete ZISI archive through `hasher-segments.js`; `upload-files.js` sends that archive to uploadDeployFunction. Pinned OpenAPI2.63.1 documents the function response's sha field and file response's sha/path. This establishes an upload-acceptance bridge under the API contract, not runtime ZIP download or source introspection. Actual sha/response behavior must still pass during the separately authorized hosted window.

`createConfigurationReceiptTransport({request,pin,files,now}).finalize` validates the actual exact-ID finalization request and its provider ACK. Exactly one named functions-scope is_secret key is allowed. No value is returned or retained in evidence. Its receipt establishes deployment-only request/provisioning under the documented contract, not effective runtime key readback or opaque-key project provenance. The secret remains private in the caller's protected transport scope and must be cleared there. No site/team/context environment endpoint is used.

`createRouteReceiptObserver({publicRequest,pin,now}).observe` checks wrong-method denial (404/405), intended read401 with a fixed synthetic nonce/generation, intended invalid Auth400, direct-function and other-API denial, then bounded invalid-body POST rate observations. No password, email, cookie, bearer token or key is sent. For each Auth route it observes exactly30 initial400s and request31=429, with no earlier Auth-route method probe consuming the clean budget. External prior traffic or ambiguous lower/higher thresholds fails closed. Auth GET denial is checked afterward, and429 at that point is rate-denial evidence only. Exact wrong-method enforcement remains required by the separate hosted Auth acceptance. The configured 30/60/IP rule is verified in the actual finalization request plus API ACK; this short sample does not independently prove every sliding-window or distributed-IP behavior. Wait for provider rule propagation before invoking the observer. Any pre-existing rate denial or incomplete behavior fails closed.

`composeProviderReceipt({publication,artifacts,configuration,routes,now})` accepts only opaque observed handles with identical candidate pins. It returns the provider section expected by existing `verifyProviderBinding`, with `preAuthProviderEvidenceReady=true` and `authAcceptance=null`. This is a pre-Auth stage, never final hosted acceptance. The unchanged final verifier still requires independently authorized fresh isolated database receipts, protected project-attested key provenance and bound real synthetic Auth acceptance. `assessApplicationReceipt` reports missing authorities when only publication is available; it is not the full composer.

# First integrated My Lockliel review candidate

This local candidate assembles actual reusable MemberExperienceWorkspace and FaithJourneyWorkspace components beneath one Next application shell at /my-lockliel/review. It is a synthetic, memory-only integration, not a connected production member service. Public homepage, global tokens/CSS, existing member navigation, Auth/session handlers, course code, migrations and hosting manifests are unchanged.

## Exposure, identity and data

The route is OFF by default. Build only with LOCKLIEL_MEMBER_REVIEW=synthetic-local and absent hosted environment (optional CONTEXT=dev). Any hosted/production context or NETLIFY marker denies exposure. This flag is not authorization and cannot prevent somebody manually hosting an already enabled static export. It is a build-time exposure guard, not runtime authentication; only synthetic data belongs in this candidate. The default synthetic identity is unknown; no private module or form mounts until an invented A/B review case is selected. There is no cookie, access token, profile lookup, Auth request or permission grant. A future live adapter requires independent server/session/consent/RLS review before any real data enters these components.

Host owns identity boundary, navigation, edition preference and reset epoch. Modules privately own visit-only UI/drafts. A/B/unknown/reset changes remount the private boundary and clear previous drafts/preferences. Dashboard/Faith navigation keeps both mounted so an ordinary tab change does not silently discard visit drafts. Hidden DOM is not an Auth boundary: unknown context omits modules entirely, and only invented review data is allowed here. Metadata-only intents never include private prayers/reflections/assessments/contact/finance. No callbacks perform writes. No photo upload, public sharing, durable storage or cloud-save claim.

Faith uses explicit synthetic editions with no approved real default or fallback. Licensed provider, trusted rights registry, default/canon/locales/attribution/cache/telemetry and private lifecycle remain unresolved. Crisis requirements are documentation, not runtime. Encouragement is versioned synthetic Scripture-reference presentation, never diagnosis, spiritual scoring or autonomous outreach.

## Shared presentation and contracts

One host header/main/navigation/h1; child workspaces use sections/scoped IDs. Host scopes controls so it does not overwrite module button styles. Navy/blue/cream/Arial values align with the recorded visual contract, with host CSS variables limited to the review shell. No global design-token migration. Final design-source selection and full accessibility acceptance still gate live integration.

Focused tests must exercise actual combined React SSR, identity/default-off/hosted denial, unique IDs, controlled preference, A/B/unknown reset and no transport/storage adapter. Actual Next static export/type/lint and browser checks of the assembled route must pass before calling the synthetic integration validated. Standalone lane tests alone are insufficient. Full release validation/authenticated live acceptance are separate gates.

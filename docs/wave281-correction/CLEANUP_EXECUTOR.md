# Disabled exact-record executor

lib/acceptance-281/cleanup-executor.mjs performs actual deletions ONLY in its own synthetic in-memory record store. It has no database/HTTP/file deletion transport and accepts no caller-supplied executor callback. createHostedRecordCleanupExecutor always returns disabled/executionAuthorized=false.

The existing reviewed record-containment reconciler establishes an exact complete initial baseline, settled creation set, project/run and two synthetic owners. prepare captures exact target IDs/digests in an opaque instance-bound plan. execute consumes the plan before operation, checks freshness and unchanged current digest, removes only those exact records by an atomic store replacement and independently reconciles the resulting baseline. Caller objects are copied/frozen. No arbitrary table, owner filter, name prefix, URL or filesystem path can be targeted.

Interrupt-before-commit leaves all records and returns uncertain with retryAllowed=false. Lost acknowledgment after commit also stops; a fresh observation can reconcile the already-deleted rows without executing another delete. A partial/unknown outcome cannot be upgraded to success. Historical records and Netlify deployment retirement remain distinct. Monotonic event/observation time prevents a post-delete snapshot being backdated before its operation. Hash-chained local audit events are immutable in the returned objects, but remain process-memory evidence—not durable or independently authenticated receipts.

The independent durable-control lane supplies signed source/project/operator/grant/snapshot contracts and filesystem attempt tracking. Those contracts are separately reviewed and not silently treated as installed authority by this executor. A true database cleanup implementation still requires a dedicated, reviewed operator-only RPC/role binding, actual ownership/run locks, trusted digests, guard-compatible cleanup state, exactly authorized rows, transaction/rollback behavior and independent readback. Selecting a real privileged principal or inventing a DELETE bypass is not authorized here. This local executor does NOT certify that missing SQL endpoint.

Tests cover exact local deletion, baseline retention, foreign and replayed handles, current-snapshot integrity, stale clocks, interruption, lost acknowledgment reconciliation, immutability and no hosted activation. No PostgreSQL fixture or SQL execution occurred. Independent review found a timestamp-rewind defect; corrected with monotonic latest-event/observation enforcement and regression test.

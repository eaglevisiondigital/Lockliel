## Consistency, zoom and assistive-technology protocol

1. On each local device, record exact source/artifact and browser/OS. At widths 320, 390, 768 and 1365 CSS pixels, inspect all worksheet steps with short and maximum permitted invented text. Do not substitute window size for actual browser zoom.
2. Use the browser's normal **200% zoom** control. Record both zoom and resulting viewport; run the dialog, forms and Share summary/actions at narrow width. Check no lost labels, clipped focus, unreachable buttons or horizontal content loss. Restore original zoom afterward. A CSS font multiplier is not this test.
3. With keyboard only, inspect focus visibility and logical order, native radio/select operation, disabled-state explanation, dialog boundaries, Back/Cancel/reset and removal. Capture expected/actual focus target as a safe control label, not DOM/private dumps.
4. Have the owner operate VoiceOver on each approved device. Record the spoken label/help/state for selects, photo states, statuses, error, steps, modal and checkbox confirmation; inspect heading/navigation/landmark order. An accessibility tree or source `aria-*` attribute is not a spoken acceptance result. Note repeated announcements or lost context rather than assuming roles are correct.
5. OS Reduce Motion changes require their normal owner permission. Capture original value and restore it. Observe the current source's actual `prefers-reduced-motion` behavior. The app currently declares animation/transition/scroll reductions in member, Faith and Share CSS; no motion being visible at baseline is not proof the OS branch ran.
6. Compare existing navy/cream/blue palette, Arial/Helvetica stack, rounded panels, form treatment and focus blue across dashboard/Faith/Share. CSS source currently shares those visual conventions, with scoped styles rather than one rewritten global token file. Inspect computed/rendered disabled/error/selected/control text, including long strings. Existing selected declared-color ratios are historical and not exhaustive rendered contrast proof. Propose differences for coordinator review; do not edit shared tokens from this checklist.
7. Record every row as PASS, FAIL or NOT TESTED for each device, with source/hash, input method and expected/actual outcome.

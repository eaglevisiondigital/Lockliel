## Architecture choice

Keep the existing static Next application plus Netlify backend-for-frontend (BFF). Reuse HTTP-only cookies, authenticated server-to-Auth validation, active-session RPC and bearer-scoped PostgREST requests. Do not assume Next SSR, a new Supabase browser client, `@supabase/ssr`, a second identity store or service-role proxy is required. Browser calls only same-origin, explicitly allowed BFF routes. The existing deployment guard deliberately disables connected preview/local traffic; do not remove it to make the review route work.

Synthetic components currently accept only synthetic owner identities and fixed fixtures. They are not ready-made authenticated components. Build a separate discriminated authenticated view contract and reviewed adapter. Do not change `status:'synthetic-owner'` to mean a real member, convert UUIDs into `synthetic-*` IDs, or infer grants from caller-provided arrays. Preserve the existing synthetic route, fixture IDs and default-OFF flags unchanged as a regression reference.
